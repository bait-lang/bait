# fast
Measures how fast the compiler compiles itself, commit by commit.

Results are published to [bait-lang/fast](https://github.com/bait-lang/fast).

## Usage
```sh
bait fast [options]
```

| Option              | Default | Description                                             |
| ------------------- | ------- | ------------------------------------------------------- |
| `-r`, `--runs`      | `5`     | Runs per commit. The fastest run is kept                |
| `-m`, `--max`       | `10`    | Maximum number of commits measured in one invocation    |
| `-c`, `--commit`    |         | Measure a single commit and print it instead of storing |
| `-n`, `--no-render` |         | Don't render `index.html`                               |
| `-p`, `--push`      |         | Commit and push the results                             |

Examples:
```sh
# Measure new commits on main and render the results
bait fast

# Check the impact of a commit without storing anything
bait fast -c 1a2b3c4
```

## How It Works
Everything happens in `~/.bait/fast/`, so your working tree is never touched:
- `bait/`: A separate clone of the bait repo that is measured
- `results/`: A clone of the results repo containing `fast.csv` and `index.html`

Commits are taken from the first-parent history of `origin/main`,
starting after the last measured one in `fast.csv`.
Without previous results, the latest `--max` commits are measured.

For each commit:
1. Check it out and bootstrap it in two stages,
   so the measured compiler (`fast.js`) is generated by itself:
   ```
   stable bait.js → fast1.js → fast.js
   ```
2. Run `fast.js --timings cli/bait.bt` `--runs` times.
   Each value is the minimum over all runs
3. Append a row to `fast.csv`. If bootstrapping or a run fails, only the commit info is stored

## Results
`fast.csv` has the following columns:

| Column       | Description                                                           |
| ------------ | --------------------------------------------------------------------- |
| `hash`       | Full commit hash                                                      |
| `date`       | Commit date                                                           |
| `total`      | Wall time of the whole compilation in ms                              |
| `parse`, `depgraph`, `check`, `transform`, `gen` | Time per compiler stage in ms     |
| `max_rss_kb` | Peak resident set size, reported by `mem.js`                          |
| `out_lines`  | Lines of the generated JS                                             |
| `src_lines`  | Lines of Bait code compiled, starting at `cli/bait.bt`                |
| `subject`    | Commit subject                                                        |

Empty values mean the build failed.

`index.html` shows the results as a table with charts.
Changes of at least 5% (and 3ms or 3KB) to the previous successful measurement are highlighted.

## Automation
The [fast workflow](../../../.github/workflows/fast.yml) runs `bait fast --push` daily.
Pushing authenticates with the `TIABEAST_BOT_TOKEN` environment variable.
